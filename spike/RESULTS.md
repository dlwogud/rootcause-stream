# D1 스파이크 결과 — VLM 사진 판독 능력 실측

> 실행 2026-11-13 · backend `claude -p` (Claude Code 구독) · model `haiku` (claude-haiku-4-5)
> 1차 96회 + 이진 변형 72회 = **168회, 실패 0건**, 평균 지연 14.5초/호출
> 재현: `python3 spike/vlm_reading_spike.py --limit 12 --repeats 2 --workers 3`

## 요약 — 설계에 반영된 3가지

1. **선택지 수가 일관성을 지배한다.** 이진 83~100% / 3~4단계 67% / 5~7분류 42%
2. **이진화가 만능은 아니다.** 이상징후는 +50%p, 게이지는 +8%p에 그침
3. **confidence는 유용한 신호다.** high 83% / medium 62% / low 40% (단조)

## 1차 — 세분 판정의 자기일관성

같은 사진을 2회 독립 판독했을 때 같은 답이 나온 비율 (n=12/과제).

| 필드 | 선택지 수 | 일관성 |
|---|---:|---:|
| `gauge_present` | 2 | **100%** |
| `is_error_code` | 2 | **100%** |
| `readable` | 2 | 91.7% |
| `fault_present` | 2 | 83.3% |
| `display_present` | 2 | 83.3% |
| `severity` | 4 | 66.7% |
| `dominant_color` | 7 | 66.7% |
| `displayed_text` | 자유 | 66.7% |
| `quartile` | 5 | **41.7%** |
| `color_band` | 5 | **41.7%** |
| `fault_type` | 7 | **41.7%** |

스키마 준수 **96/96 (100%)**. `quartile` 불일치 7건 중 인접구간 3 · 원거리 3 → 경계 노이즈가 아니라 절반은 사실상 무작위.

## 2차 — 이진 변형

| 과제 | 세분 | 이진 | 변화 |
|---|---:|---:|---:|
| 이상 징후 (7분류 → 유무) | 41.7% | **91.7%** | **+50.0%p** |
| 경고등 (7색 → 점등 여부) | 66.7% | 66.7% | +0.0%p |
| 게이지 (4분위 → 범위 이탈) | 41.7% | 50.0% | +8.3%p |

대상이 실제로 찍혔고 `readable=True`인 사진만 추리면:

| 과제 | n | 일관성 |
|---|---:|---:|
| `fault_binary` | 5 | **100%** |
| `indicator_binary` | 3 | **100%** |
| `gauge_binary` | 11 | **45.5%** ← 필터링해도 개선 없음 |

### 게이지가 실패한 이유 — 모델이 아니라 과제 정의

불일치 6건 전부 `gauge_present=True`이고 confidence는 medium/high였다.
원인은 **"정상 범위를 벗어났는가"가 정상 범위를 모르면 답할 수 없는 질문**이라는 것이다.
컬러 밴드가 없는 게이지가 대부분이라 모델이 매 호출마다 다른 기준을 가정한다.

→ **게이지 수치/범위 판독은 설계에서 제외.** 대신 매뉴얼의 기준값(예: 공압 0.5 MPa,
`spotweldinc_users.pdf` p6)을 근거로 **작업자에게 직접 묻는다**:
*"게이지가 0.5 MPa 이상입니까? 예/아니오"*

LLM이 못 하는 것을 측정해서 사람에게 넘긴 것이고, 이 프로젝트의 주제와 오히려 일치한다.

## confidence 의 타당성

| confidence | 일관성 |
|---|---:|
| high | 15/18 = **83.3%** |
| medium | 8/13 = 61.5% |
| low | 2/5 = 40.0% |

**단조 관계가 있다.** 설계 초안에서 "confidence를 믿지 말라"고 했던 것은 과한 해석이었다.
선행 연구(arXiv 2608.17723)의 주장은 "high에서도 오답이 *가능*하다"이지 무상관이 아니다.

→ 확정 설계: **confidence를 1차 필터로 사용하되 단독 확정 근거로는 쓰지 않는다.**
high가 아니면 재촬영 요청, high여도 가설을 뒤집는 판독이면 2회 독립 재판독.

## 채택 판정

| 판독 과제 | 판정 | 근거 |
|---|---|---|
| 이상 징후 유무 (부식·균열·마모·누유) | ✅ **채택** | 91.7%, readable만 100% |
| 디지털 에러코드 유무 | ✅ **채택** | `is_error_code` 100% |
| 경고등 점등 여부 | 🟡 조건부 | 대상 명확 시 100%이나 n=3 |
| 게이지 범위/수치 | ❌ **제외** | 50%, 이진화로도 개선 안 됨 |
| 유형 7분류 / 4분위 | ❌ 제외 | 42% |

## 한계

- 과제당 12장 × 2회로 **표본이 작다.** 방향성은 분명하나 확정적이지 않다
- 정답 라벨이 아직 없다 — 측정한 것은 **일관성**이지 정확도가 아니다.
  정확도는 `spike/out/review.html`에서 라벨링 후 `--score`로 산출한다
- Commons 이미지에 과제 무관 사진이 섞여 있다(예: `gauge_zone`에 커피머신).
  `*_present` 필드로 걸러지지만 유효 표본을 줄인다
- 단일 모델(haiku)만 측정했다. sonnet/opus 비교는 D13 본 측정에서

## 부수 발견 — 런타임 설계에 반영

1차 실행 중 모델이 스키마를 요구받고도 **JSON 객체 대신 배열**을 반환해 루프가 중단됐다
(1/20 수준). `claude -p`에는 `output_config.format` 같은 스키마 강제 장치가 없다.

→ `app/agent/loop.py`에 그대로 들어갈 패턴: **응답 형태 검증 + 실패 격리 + 증분 저장.**
한 번의 비정상 응답이 전체 루프를 죽이면 안 된다.
→ 서비스 런타임은 스키마 강제가 되는 **API 백엔드**를 쓴다.
