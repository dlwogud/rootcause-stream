# 04. LLM/VLM 기술별 도입 목적

> 원칙: 기술을 나열하지 않는다. **각 기술은 "껐을 때 무엇이 망가지는지"를 한 줄로 말할 수 있어야 레포에 들어간다.**
> 이 표가 발표자료의 핵심 슬라이드가 되고, 오른쪽 열이 `10-evaluation.md`의 ablation 실험 목록이 된다.

| # | 기술 | 역할 (왜 필요한가) | 끄면 무엇이 망가지는가 | 측정 지표 |
|---:|---|---|---|---|
| 1 | 스트림 윈도우 집계 | 알람 버스트 탐지, 선후관계·공발생 행렬 추출 | 알람 수백 건 원문을 LLM에 투입 → 토큰 폭증, 근본원인 정확도 하락 | M1, 토큰/건 |
| 2 | 가설 생성 (LLM, adaptive thinking) | 파생 알람 제거 후 원인 후보 3~5개 | 단일 추측만 남아 오진 시 복구 경로가 없다 | M1, M2 |
| 3 | **Multimodal RAG (P&ID 도면)** | 계통 연결 관계 확인으로 가설 구분 | 도면에만 있는 연결관계 질문 실패 → 가설 구분율 하락 | M3 |
| 4 | Hybrid Search (BM25 + 벡터) | 매뉴얼 절·조치 절차 검색 | 설비명/부품명 정확 일치 검색 실패 (벡터 단독의 약점) | M5 |
| 5 | Reranking (bge-reranker) | 검색 상위 후보 재정렬 | 유사 설비명 오검색이 조치 카드에 그대로 유입 | M5 |
| 6 | Tool Calling (strict) | 센서 시계열·사례·도면 조회 | 초기 알람 정보만으로 판단 → 가설 점수가 갱신되지 않는다 | M1, 루프 길이 |
| 7 | **촬영 요청 설계 (Structured Output)** | 어떤 사진이 어떤 가설을 가르는지 계산해 지시 | 작업자가 무엇을 찍을지 모른다. 사진을 받아도 정보이득이 0에 가깝다 | **M4** |
| 8 | **VLM 현장 사진 판독** | 센서에 없는 정보로 가설 확정 | 가설 미확정 상태로 종료 → 서비스의 존재 이유가 사라진다 | M6 |
| 9 | Reflection / Self-Correction | 증거↔결론 정합성 재검토, 근거 없는 단정 차단 | 인용 없는 결론 발생률 상승 | M7 |
| 10 | Long-term Memory (사례 적립) | 동일 유형 재발 시 즉시 응답 | 매번 처음부터 추론 → 지연·토큰 증가, 현장 신뢰 하락 | M8, 토큰/건 |
| 11 | Document Citations | 조치 단계마다 매뉴얼 쪽수 인용 | "AI가 말했다"만 남는다. 작업자가 검증할 수 없다 | M7 |
| 12 | LLM-as-Judge (평가 하네스) | 벤치마크 자동 채점 | **정량 성과표 제작 불가** → 발표 경쟁력 상실 | — |

## 기술별 구현 메모

### 3. Multimodal RAG — 텍스트 RAG가 못 하는 것

매뉴얼을 PyMuPDF로 처리할 때 페이지를 2종으로 분류한다.

- **텍스트 페이지** → 청킹 후 하이브리드 색인
- **도면·플로우차트 페이지** → 페이지 전체를 이미지로 렌더(200dpi), VLM으로 **구조 서술을 생성**해 그 서술을 색인하고, 원본 이미지는 Files API에 올려 `file_id`를 함께 저장

조회 시: 서술 텍스트로 검색 → 히트한 페이지의 **원본 이미지를 VLM에 다시 투입**해 구체 질의에 답하게 한다. (서술만 보고 답하면 도면의 세부 연결을 놓친다.)

> 발표 포인트: "텍스트 RAG로는 `V-203이 어느 실린더에 연결되는가`를 영원히 답할 수 없다. 그 정보는 선으로만 그려져 있다."

### 7. 촬영 요청 설계 — 이 프로젝트의 지적 핵심

출력 스키마:

```json
{
  "requests": [
    {
      "target": "상부 전극 팁 선단",
      "how_to_shoot": "팁 끝에서 10cm, 측면 각도, 플래시 ON",
      "discriminates": ["H1", "H3"],
      "if_observed": {
        "버섯형 변형 또는 표면 산화": {"H1": "support", "H3": "weaken"},
        "선단 형상 정상 + 광택 유지": {"H1": "refute", "H3": "support"}
      },
      "why_this_photo": "H1과 H3은 센서 신호가 동일하게 나타난다. 팁 형상은 둘을 가르는 유일한 관찰이다."
    }
  ]
}
```

`if_observed`를 **사진을 받기 전에** 선언하게 하는 것이 중요하다. 사후에 해석을 맞추면 정보이득을 측정할 수 없고, Agent가 사진을 본 뒤 결론에 맞춰 이야기를 만들게 된다.

### 8. VLM 사진 판독 — 판독 과제를 VLM이 잘하는 쪽으로 한정

**아날로그 계기의 정밀 수치 판독은 VLM의 약점이다.** 1주차 스파이크에서 실측하되, 설계는 처음부터 다음 4종으로 한정한다.

| 판독 과제 | 난이도 | 비고 |
|---|---|---|
| ① 디지털 표시기·에러코드 문자 판독 | 낮음 | VLM이 가장 잘하는 영역 |
| ② 상태 표시등 색 분류 | 낮음 | |
| ③ 게이지 바늘의 **구간** 판정 (적/녹/황, 정상/저하/과다) | 중간 | 정밀 수치 아님 |
| ④ 정성 이상 판정 (마모 형상, 산화, 누유, 파손) | 중간 | 참조 이미지를 few-shot으로 투입 |
| ✗ 바늘 각도 → 정확한 수치 환산 | 높음 | **채택하지 않는다** |

출력에 `confidence`와 `unreadable_reason`을 필수 필드로 둔다. 판독 실패를 "모르겠다"로 반환할 수 있어야 Agent가 재촬영을 요청할 수 있다.

### 9. Reflection — 근거 없는 단정 차단

가설 점수를 갱신하는 모든 출력에 `cited_evidence_ids`를 필수로 요구하고, 코드에서 **존재하지 않는 id를 인용하면 거부하고 재생성**한다(최대 2회). 이 거부율 자체가 M7 지표가 된다.

### 10. Long-term Memory — 장식이 아닌 이유

사례는 다음 서명(signature)으로 색인한다: `[알람 패턴 해시, 확정 원인 라벨, 공정 변수 이상 방향 벡터]`. 새 incident에서 서명 유사도가 임계치를 넘으면 Agent의 1단계 프롬프트에 **과거 사례 2건을 주입**한다.

측정(M8): 사례 DB가 빈 상태 vs 사례 40건 적립 상태에서 동일 incident 집합을 처리할 때
- 근본원인 정확도 변화
- **루프 길이(tool 호출 수)와 토큰/건 감소** ← 여기서 효과가 선명하게 나온다

> 발표 포인트: "사례가 쌓이면 정확도만 오르는 게 아니라 **비용이 내려간다.** 40건 적립 후 건당 토큰이 N% 감소했다."
