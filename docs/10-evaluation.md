# 10. 테스트 및 성능 평가 방법

> **평가 하네스를 1주차에 만든다.** 마지막에 만들면 발표자료에 숫자가 없는 상태로 11/28을 맞는다.
> 발표 경쟁력의 대부분이 이 문서에서 나온다.

## 평가 케이스

`eval/cases/*.yaml`. 각 케이스는 `{tier, window, truth, notes}`.

| Tier | 수 | 정답 출처 | 성과표 표기 |
|---|---:|---|---|
| A 실측 | 3 | 선행 프로젝트 permutation test (p=0.0179)로 입증된 실제 공정 shift | 주 지표 |
| B 합성 | 7종 × 5 = 35 | 물리 기반 주입 결함 | **"주입 결함 민감도"로 분리 표기** |
| C 데이터 품질 | 1(+파생 구간) | 실제 발견된 26.8% 중복 블록 | 주 지표 |

**Tier A가 3건뿐인 것을 숨기지 않는다.** 발표에서 먼저 말하고, Tier B를 난이도 축으로, 외부 데이터셋 2종을 이전 검증으로 보완한다.

## 메트릭

| ID | 메트릭 | 정의 | 왜 이걸 재는가 |
|---|---|---|---|
| **M1** | 근본원인 정확도 | Tier별 top-1 / top-3 일치율 | 서비스의 1차 목적 |
| **M2** | 파생 알람 제거 | 동일 원인 귀속 알람 판정의 P/R/F1 | "47건 → 3건"의 정량 근거 |
| **M3** | 가설 구분율 | 도면 조회 전후 가설 분포 엔트로피 감소(bits) | Multimodal RAG가 실제로 일을 했는가 |
| **M4** | **촬영 요청 정보이득** | H(P_before) − H(P_after), bits. **무작위 촬영 요청 대조군과 비교** | ★ 이 프로젝트의 지적 주장 |
| **M5** | 매뉴얼 검색 품질 | 수동 라벨 30쿼리에 대한 nDCG@5 / Recall@5 | Hybrid·Rerank 기여 |
| **M6** | VLM 판독 정확도 | 판독 과제 4종별 정확도 + 판독 거부율 | VLM 한계의 정직한 공개 |
| **M7** | 인용 무결성 | ① 미존재 증거 id 인용률 ② 인용 없는 조치 step 비율 | 환각 방어의 측정 |
| **M8** | 메모리 효과 | 사례 0건 vs 40건: 정확도 / 루프 길이 / 토큰 | Long-term Memory가 장식이 아님을 증명 |
| C1 | 비용 | 사건당 USD, 캐시 적중률 | 운영 현실성 |
| C2 | 지연 | 스텝별 p50 / p95 | 실시간 주장의 근거 |

### M4 — 정보이득, 자세히

이게 발표의 차별 포인트이므로 정의를 엄격하게 둔다.

1. 촬영 요청 **직전** 가설 점수를 정규화해 분포 `P_before`를 만들고 섀넌 엔트로피 `H_before`를 계산한다.
2. 사진 판독 후 재평가된 분포로 `H_after`를 계산한다.
3. 정보이득 `IG = H_before − H_after` (bits).
4. **대조군**: 동일 incident에서 Agent가 아니라 **무작위로 선택한 관찰 대상**의 사진을 투입해 `IG_random`을 계산한다.
5. 보고: `IG_agent` vs `IG_random`의 분포 차이 + 쌍별 검정.

추가로 **사전 선언 적중률**을 함께 본다. `if_observed`를 사진 수신 전에 저장했으므로(`06-database.md`), Agent가 예측한 관찰 범주와 실제 판독 범주가 일치한 비율을 측정할 수 있다. 사후 합리화가 아님을 보이는 장치다.

> 발표 한 문장: **"Agent가 요청한 사진은 무작위 사진보다 가설 불확실성을 N배 줄였다."**
> 이 문장이 "사람을 센서로 쓴다"는 주장을 숫자로 바꾼다.

## Ablation 실험

`eval/run.py --config configs/ablation/<name>.yaml`. 전체는 Batches API로(50% 할인).

| 조건 | 끄는 것 | 기대 영향 메트릭 |
|---|---|---|
| `full` | — (기준선) | 전부 |
| `no_window` | 스트림 집계 → 알람 원문 전량 투입 | M1↓, 토큰↑ |
| `no_diagram` | 도면 Multimodal RAG | **M3↓**, M1↓ |
| `no_rerank` | bge-reranker | M5↓ |
| `bm25_only` / `vector_only` | 하이브리드 한쪽 | M5↓ |
| `no_tools` | 시계열·사례 조회 | M1↓, 루프길이↓ |
| `random_photo` | 촬영 요청 설계 → 무작위 대상 | **M4↓** (대조군) |
| `no_photo` | 사진 단계 전체 | **M1↓ 가장 크게** — 서비스 존재 이유의 증명 |
| `no_reflection` | 재검토 단계 | M7↓ |
| `no_memory` | 사례 조회 | M8, 토큰↑ |
| `effort_low` | 가설 생성 effort high→low | M1 변화 / 비용↓ (비용-품질 곡선) |
| `model_sonnet` | 추론 모델 Opus 5→Sonnet 5 | M1 변화 / 비용↓ |

**마지막 두 조건이 중요하다.** "비싼 모델이 꼭 필요했는가"에 숫자로 답할 수 있으면 설계 성숙도로 평가받는다. 답이 "Sonnet 5로 충분하다"로 나와도 좋다 — 그건 발견이다.

## 단위 테스트 / 회귀

| 대상 | 테스트 |
|---|---|
| `stream/detectors.py` | **선행 프로젝트 수치 재현 대조** — 2σ 관리도가 동일 데이터에서 3/3 탐지, 오경보 0/5를 재현하는지. 이 테스트가 실패하면 이식이 잘못된 것이다 |
| `agent/schemas.py` | structured output 스키마 유효성 (잘못된 LLM 출력 거부 확인) |
| `agent/loop.py` | 중단→재개 왕복: 상태를 저장하고 새 프로세스에서 로드해 동일 결과가 나오는지 |
| `retrieval/hybrid.py` | RRF 병합 결정성 |
| `llm/client.py` | 모델별 파라미터 분기 (Haiku에 effort를 보내지 않는지) |
| `memory/cases.py` | 서명 유사도 임계치 경계 |
| 타임아웃 워커 | `expires_at` 경과 시 `no_response` 주입 후 정상 종료 |

LLM 호출이 필요한 테스트는 **녹화된 응답(fixture)으로 재생**한다. CI에서 매번 API를 때리면 비용과 비결정성이 생긴다. 실호출 테스트는 `-m live` 마커로 분리.

## 재현성 — 선행 프로젝트 방식 계승

`~/kamp-welding`에서 산출물 진위 검사를 파이프라인 종료 조건으로 걸었던 방식을 그대로 가져온다.

```
bash run_all.sh
  ├─ 1..n  파이프라인 전 단계
  ├─ 90    보고서/README의 모든 인용 수치를 원본 CSV와 대조 → 불일치 시 exit 1
  └─ 91    기대 산출물 목록을 문서에서 도출 → mtime·SHA-256 검증 → stale/missing 시 exit 1
```

제출 전 `outputs/`를 비우고 전체 재실행해 전부 FRESH / PASS를 확인한다. **발표자료의 모든 숫자가 재현 가능하다는 것 자체가 평가 항목이다.**
