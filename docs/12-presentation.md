# 12. 발표 전략

> 선발은 **자료를 훑어보고** 결정된다. 훑어봐서 뽑히는 자료에는 네 가지가 있다.
> ① 10초 안에 이해되는 문제 ② 다른 자료에 없는 화면 한 장 ③ **숫자** ④ 실제로 돌아간다는 증거

## 프레이밍 — 첫 슬라이드가 선발을 가른다

❌ **"제조 설비 근본원인 진단 AI"** → 심사위원은 공장 관제실 경험이 없다. 공감되지 않고 넘겨진다.

✅ **"LLM이 모르는 것을, 사람의 눈을 빌려 알아내는 Agent"**

같은 프로젝트다. 두 번째가 선발된다. 도메인은 **검증 수단**으로 두 번째 슬라이드에 둔다.

### 오프닝 서사 (3문장)

> 작년에 같은 용접 공정 데이터로 "용접점 단위 불량 예측은 이 데이터로 불가능하다"를 다섯 겹으로 입증했습니다. 공정 이상은 작업일 단위 수준 이동으로만 탐지됐고, 거기서 분석은 끝났습니다.
>
> 그런데 현장에 남은 질문은 **"이상이 감지됐다. 그래서 작업자는 무엇을 해야 하는가"**였습니다.
>
> 그 답은 센서에 없었습니다. **매뉴얼의 도면과, 현장에 가서 눈으로 봐야 하는 것**에 있었습니다. 그래서 이번엔 LLM과 VLM으로 그 간극을 메웠습니다.

이 서사가 하는 일:
- 선행 작업의 엄격함을 증명한다 (분석 역량 입증)
- **LLM/VLM을 쓸 이유가 임의적이지 않다** — 정보가 문서와 사진에 있어서 쓴 것이다
- "LLM 없으면 불가능"이 논증 없이 자명해진다

## 시연 장면 3개 (순서 고정)

### ① 수렴 — 10초

알람 47건이 화면에 폭주한다. `파생 알람 숨기기` 토글 클릭 → **3건으로 줄어든다.**

말할 것: "47건 중 44건은 결과였습니다. 원인은 3개 후보로 좁혀졌습니다."

### ② 사람을 센서로 — 60초, 이게 핵심이다

가설 H1과 H3이 센서로 갈라지지 않는다. Agent가 촬영 요청을 생성한다.
화면에 **QR 코드**가 뜬다. → **발표자가 폰으로 스캔하고 그 자리에서 사진을 찍는다.** → 업로드 → VLM 판독 → **가설 점수 바가 움직인다** (0.42 → 0.91).

말할 것: "Agent는 자기가 모른다는 것을 알았고, **어떤 사진이 두 가설을 가르는지 계산해서** 요청했습니다. 지금 찍은 사진으로 확정됐습니다."

> **라이브로 찍는 것이 중요하다.** 미리 준비한 사진이면 "쉬운 걸 골라왔다"는 의심을 받는다. 라이브 촬영은 그 의심을 원천 차단한다. D16에 리허설 3회.

### ③ 검증 가능성 — 20초

조치 카드의 `📄 매뉴얼 4-3절 p.37`을 클릭 → 매뉴얼 원문과 도면 페이지가 뜬다.

말할 것: "모든 조치 단계는 매뉴얼 쪽수를 인용합니다. 인용이 없는 단계는 생성 단계에서 거부합니다."

## 숫자 — 반드시 들어가야 하는 표 2개

```
① 근본원인 진단 정확도 (Tier A 실측 / C 데이터품질 / B 합성 분리)
② 구성요소 기여도 — 각 기술을 껐을 때의 Δ
```

②가 **"LLM의 다양한 기술을 도입했는가"(배점 30점)에 대한 답**이다. 기술 로고 10개를 나열한 슬라이드보다 이 표 한 장이 강하다. 로고 슬라이드는 "주장"이고 이 표는 "증거"다.

그리고 **M4 한 문장**:

> "Agent가 요청한 사진은 무작위로 선택한 사진보다 가설 불확실성을 N배 줄였습니다."

이 문장이 "사람을 센서로 쓴다"를 수사에서 측정으로 바꾼다.

## 한계를 먼저 말한다 (설계 성숙도 점수)

발표에 반드시 넣는다. 숨기면 질의응답에서 더 크게 깨진다.

| 한계 | 어떻게 말하는가 |
|---|---|
| Tier A 실측 케이스가 3건 | "표본이 작습니다. 그래서 합성 결함 35건을 **별도 표기**로 함께 제시하고, 외부 데이터셋 2종으로 이전 검증했습니다" |
| 아날로그 계기 정밀 판독 불가 | "VLM은 바늘 각도를 수치로 환산하지 못합니다. 그래서 판독 과제를 **구간 판정**으로 한정했고, 정확도를 과제 유형별로 공개합니다" |
| 실제 용접기 접근 불가 | "동형 계기로 시연합니다" |
| 정답 라벨 출처 | "**제가 만들지 않았습니다.** 선행 분석에서 permutation test로 입증한 실제 공정 shift입니다. 주입한 결함은 별도 표기했습니다" |

마지막 항목이 가장 중요한 방어선이다. 산업 AI 프로젝트에 대한 날카로운 질문은 거의 항상 **"당신이 심은 정답을 당신이 찾은 것 아닌가"**다.

## 예상 질의 (D16에 답을 외운다)

| 질문 | 답의 핵심 |
|---|---|
| LLM 없이 규칙 엔진으로 못 하나? | 도면의 선 연결과 사진의 마모 형상은 규칙으로 읽을 수 없다. 기술별 ablation Δ가 근거 |
| 기술을 너무 많이 넣은 것 아닌가? | 12개 전부에 대해 껐을 때의 Δ를 측정했다. 기여가 없는 것은 제거했다 (실제로 제거한 게 있으면 그걸 말한다) |
| Self-RAG / Reflection은 어디서 작동하나? | 증거 id 인용 검증 단계. 미존재 id 인용률이 M7 |
| 왜 Opus 5를 썼나? Sonnet으로 충분하지 않나? | `model_sonnet` ablation 결과를 그대로 제시. 충분하다고 나왔으면 그대로 말한다 |
| 사진을 작업자가 안 찍으면? | 타임아웃 15분 후 `no_response`로 재개, 사진 없이 최선의 결론을 낸다. 그 경우 정확도도 측정했다 |
| 실시간이라고 할 수 있나? | 스텝별 p50/p95 제시. Flink 처리량도 (2단계 완료 시) |
| 다른 설비로 확장 가능한가? | 매뉴얼과 도면만 교체하면 된다. 단 검증은 RSW 1종뿐임을 명시 |
